# 海报拆图与可编辑画板

把海报或截图整理成 **独立图片素材 + 可编辑文字 + 排好版的网页画板**，通过网页按钮复制到 Figma。

这是一套供 Codex 使用的 **Skill、辅助脚本和网页模板**。它需要 AI 根据原图识别元素、处理素材并重建排版；仓库本身不是上传图片就能自动完成所有工作的在线服务。

## 能做什么

- 将艺术版头、装饰物、截图与正文分开处理。
- 将需要去底的版头、奖杯等装饰物处理成透明 PNG，并检查真实透明通道。
- 保留照片、游戏截图等矩形图片的原背景。
- 将正文、课程标题、标签等重建为可编辑文字。
- 默认使用 **阿里巴巴普惠体 `Alibaba PuHuiTi`，不带 3.0**，支持 Regular / Bold。
- 生成带「复制画板到 Figma」按钮的本地网页，无需安装 Figma 设计插件。
- 检查图片是否内嵌、字体是否匹配，以及修改后的网页是否仍在复制旧数据。

## 快速使用

### 1. 安装 Skill

将本仓库下载、解压后，把包含 `SKILL.md` 的整个文件夹命名为 `poster-to-editable-board`，安装到你使用的 Codex 环境支持的本地 Skill 目录。

也可以把发布后的 GitHub 仓库链接发给 Codex，并说：

> 帮我安装这个仓库里的 Skill：这里粘贴仓库链接。

安装完成后，在 Skill 列表中确认能看到 **海报拆图与可编辑画板**。如果暂时未出现，可以重新打开 Codex。

### 2. 上传海报并提出需求

最明确的调用方式：

```text
使用 $poster-to-editable-board 拆这张海报，按默认流程生成可复制画板。
```

在支持自动匹配 Skill 的环境中，也可以说：

```text
用拆图 Skill 处理这张图。
```

```text
把这张海报分层，正文可以编辑，装饰图片要透明底。
```

不需要每次完整复述要求。默认设置已经记录在 [SKILL.md](SKILL.md) 中；本次任务中明确提出的要求优先。

### 3. 复制到 Figma

1. 打开生成结果中的本地网页地址。
2. 点击 **复制画板到 Figma**，等待「已复制」提示。
3. 在 Figma Design 画布中按 **⌘V**，Windows 使用 **Ctrl+V**。
4. 双击正文进行编辑，图片素材可独立移动。

本地网页需要服务保持运行。请通过给出的 `http://127.0.0.1:端口/` 地址打开；浏览器如询问剪贴板权限，请允许。内置预览无法复制时，用 Chrome 或 Edge 打开。

## 字体说明

默认字体为不带版本号的 **阿里巴巴普惠体 / Alibaba PuHuiTi**，不是 **Alibaba PuHuiTi 3.0**。

- 先检查本机是否已安装对应字体，已有时直接使用。
- 网页通过项目中的字体文件与 `@font-face` 加载 Regular / Bold。
- 放入普通文件夹不等于安装字体。Figma 编辑时也需要能访问对应字体；网页版通常需要官方字体助手。
- 字体助手与 Figma 设计插件是不同的工具，本 Skill 不会自动安装它们。
- 仓库不包含字体文件，请自行提供可使用的字体。

可以在请求中明确指定其他字体，Skill 会以当前要求为准。

## 运行环境

| 组件 | 用途 |
| --- | --- |
| 支持本地 Skill、文件读写和脚本运行的 Codex 环境 | 执行拆图与重排流程 |
| 可用的图像编辑工具 | 按需去背景，输出透明素材 |
| Node.js + Playwright + sharp | 捕获网页、检查素材与剪贴板 |
| Chrome 或 Playwright Chromium | 渲染画板与测试复制按钮 |
| Python 3 | 检查字体内部名称、启动本地静态服务器 |
| 用户提供或已安装的字体 | 正确显示与编辑指定字体 |

已有依赖时优先复用。需要自行配置脚本环境时，可以在仓库根目录安装：

```sh
npm install --no-save playwright sharp
npx playwright install chromium
```

如果依赖位于其他位置，设置 `BOARD_NODE_MODULES`；使用已有 Chrome 时，可以设置 `BOARD_CHROME` 为可执行文件路径。具体配置见 [执行指南](references/execution.md)。

网页最终的复制按钮读取已生成的数据，不会在每次点击时调用模型。首次识别、图像编辑和排版仍需要相应工具；使用费用以所用环境为准。

## 工作流程

```text
原始海报
  → 识别元素与转录文案
  → 提取图片、处理透明背景
  → 检查指定字体
  → 重建 HTML/CSS 画板
  → 生成 Figma 剪贴板数据
  → 验证透明通道、文字、字体和复制按钮
  → 交付网页与素材包
```

辅助脚本处理的是已经重建的网页。它们不会单独完成原图的文字识别或自动拆层。

## 文件结构

```text

├── scripts/

│   ├── verify-board.cjs          检查内容与快照是否过期
│   └── board-lib.cjs             配置、指纹与数据校验
├── references/
│   └── execution.md              配置格式和执行命令
└── assets/
    └── web-shell/
```

`assets/web-shell/` 是模板，需要配合每张海报生成的 `board.html`、`board-config.json`、图片素材与剪贴板数据使用。

## 生成结果

通常包括：

- 可预览和复制的网页。
- 画板 HTML/CSS 与独立图片素材。
- 指定字体配置。
- `figma-clipboard.html`：准备好的复制数据。
- `capture-report.json`：尺寸、节点数量、字体、透明素材与文件指纹。
- 画板截图和简短检查记录。

**复制数据是固定快照。** 修改文字、字体、图片或布局后，必须重新运行捕获与验证。验证脚本会拒绝与源文件不一致的旧快照。

## 验证范围与限制

- 已在示例海报上验证两张透明 PNG、可编辑文字数据、指定字体、图片内嵌及重复复制。
- 已验证源文件修改后能够识别旧快照，并区分 `Alibaba PuHuiTi` 与 `Alibaba PuHuiTi 3.0`。
- 剪贴板结构验证通过，不等于已经在每个 Figma 环境中完成粘贴验证。最终字体匹配、渐变及裁切效果需要在目标文件中确认。
- 图像编辑可能改变细节，背景与复杂特效可能需要近似重建；不能保证恢复原始设计文件或完全无损拆图。
- 本流程使用 Figma 官方网页捕获脚本生成剪贴板数据，仓库不捆绑该脚本。官方接口改变时，可能需要调整流程。

## 发布到自己的 GitHub

新建仓库后，将本目录中的文件和子文件夹一起上传，使 **README.md 与 SKILL.md 位于仓库根目录**，然后提交保存。

这个文件包包含可复用的流程、脚本和模板，不包含个人海报原图、本机字体文件、账号信息或生成的画板数据。发布仓库即可保存和分享 Skill；要提供在线拆图服务，还需要另外开发和部署。
